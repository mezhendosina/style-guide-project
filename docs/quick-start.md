# Быстрый старт

Эта страница помогает применить стайл-гайд к новому документу за пять шагов.

## 1. Назовите задачу читателя

Сформулируйте её как наблюдаемый результат: «создать заказ», «проверить статус платежа», «настроить webhook». Если в заголовке нельзя использовать глагол, вероятно, границы документа ещё неясны.

## 2. Выберите тип документа

| Если читателю нужно… | Используйте | Основа |
| --- | --- | --- |
| решить задачу по шагам | практическое руководство | [шаблон how-to](patterns/how-to.md) |
| узнать точный контракт | справочник метода | [шаблон метода API](patterns/api-method.md) |
| понять концепцию | объясняющая статья | контекст → модель → ограничения → связи |
| устранить сбой | инструкция по диагностике | симптом → причина → решение → проверка |

Не смешивайте обучение, справочник и диагностику на одной странице. Свяжите отдельные страницы ссылками.

## 3. Соберите проверенные данные

До написания подтвердите:

- актуальный URL и HTTP-метод;
- обязательные поля, типы и ограничения;
- авторизацию и права доступа;
- успешный ответ и известные ошибки;
- особенности повторного запроса и ограничения частоты.

Не восстанавливайте контракт по памяти. Сверяйтесь с реализацией, OpenAPI-описанием и владельцем API.

## 4. Напишите минимальный путь

Сначала покажите самый короткий рабочий сценарий. Затем добавьте варианты и исключения. Каждый шаг должен содержать одно действие и, когда это полезно, ожидаемый результат.

```text
Действие → пример → ожидаемый результат
```

Используйте один термин для одного понятия и обращайтесь к читателю на «вы».

## 5. Проверьте и отправьте на ревью

- Пройдите [редакторский чек-лист](patterns/checklist.md).
- Запустите `python3 scripts/check_docs.py`.
- Запустите `mkdocs build --strict`.
- Откройте Pull Request и укажите, для какой задачи читателя сделано изменение.

!!! success "Документ готов"

    Незнакомый с изменением человек может выполнить задачу только по опубликованному тексту, а приведённые запросы дают описанный результат.
