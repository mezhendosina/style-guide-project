# Оформление

Оформление помогает распознавать тип информации. Один визуальный приём должен иметь одно устойчивое значение.

## Выделяйте элементы интерфейса и кода

Используйте моноширинное начертание для:

- имён параметров и полей — `order_id`;
- значений — `pending`;
- HTTP-методов и путей — `POST /v1/orders`;
- имён файлов и команд — `mkdocs.yml`, `mkdocs serve`;
- горячих клавиш — `Ctrl+C`.

Названия кнопок, вкладок и разделов интерфейса выделяйте полужирным: нажмите **Создать ключ**. Не заключайте обычные термины в кавычки только ради акцента.

## Используйте смысловые примечания

| Тип | Назначение |
| --- | --- |
| `note` | дополнительный контекст |
| `tip` | необязательный способ упростить работу |
| `warning` | риск потери данных, денег, доступа или совместимости |
| `danger` | непосредственное необратимое или критическое действие |
| `example` | развёрнутый образец |

Ставьте предупреждение до действия. Не используйте больше двух примечаний подряд: если всё важно, переработайте структуру.

## Оформляйте код как рабочий пример

Указывайте язык блока, сохраняйте разумную длину строки и добавляйте контекст перед примером. После блока объясняйте неочевидный результат.

```bash
curl --request GET \
  --url https://api.example.com/v1/orders/order_123 \
  --header "Authorization: Bearer YOUR_API_KEY"
```

Не используйте скриншот вместо кода: текст можно скопировать, найти и прочитать экранным диктором.

## Показывайте заполнители явно

Заполнители пишите прописными латинскими буквами с подчёркиваниями: `YOUR_API_KEY`, `PROJECT_ID`. Если заменить нужно часть строки, объясните границы замены в тексте.

Не используйте угловые скобки в командах: оболочка может воспринять их как перенаправление.

## Оформляйте изображения

- Добавляйте содержательный альтернативный текст.
- Обрезайте не относящиеся к задаче области.
- Не передавайте смысл только цветом или стрелкой.
- Указывайте элементы интерфейса текстом рядом со скриншотом.
- Обновляйте изображение вместе с интерфейсом.

## Соблюдайте единый Markdown

- Используйте ATX-заголовки: `## Раздел`.
- Ставьте пустую строку вокруг списков и блоков кода.
- Используйте `-` для маркированных списков.
- Не применяйте ручные переносы `<br>` для построения макета.
- Ссылки на страницы проекта делайте относительными.
