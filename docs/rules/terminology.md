# Терминология

Один термин обозначает одно понятие. Этот словарь фиксирует предпочтительные формы для русскоязычной документации API.

## Основной словарь

| Пишите | Не пишите | Комментарий |
| --- | --- | --- |
| API | апи, API-интерфейс | Аббревиатуру не склоняем |
| метод API | эндпоинт, ручка | В URL допустимо «конечная точка» только при необходимости |
| запрос | реквест | Для HTTP request |
| ответ | респонс | Для HTTP response |
| тело запроса | тело сообщения | Если речь именно об HTTP-запросе |
| заголовок | хедер | Например, заголовок `Authorization` |
| API-ключ | ключ API, апикей | Через дефис |
| токен доступа | access token | Английскую форму приводим только для сопоставления с интерфейсом |
| webhook | веб-хук, вебхук | Если это официальное название сущности продукта |
| идентификатор | ID, айди | В имени поля сохраняем `id` |
| email | e-mail, электронная почта | Для адреса; «письмо» — для сообщения |
| JSON-объект | JSON объект | Определение после аббревиатуры — через дефис |
| база данных | БД | Аббревиатура допустима после расшифровки |
| учётная запись | аккаунт | Кроме официального названия элемента интерфейса |

## Имена сущностей

Если имя программной сущности показано в коде или интерфейсе, сохраняйте его регистр и написание: `order_id`, `Idempotency-Key`, **API Keys**. Не переводите идентификаторы.

В пояснительном тексте используйте русское название: «Передайте идентификатор заказа в поле `order_id`».

## Новые термины

Перед добавлением термина:

1. Проверьте, нет ли уже принятого обозначения.
2. Сравните термин в API, интерфейсе и службе поддержки.
3. Выберите форму, понятную целевой аудитории.
4. Добавьте определение и нежелательные варианты.
5. Найдите старые варианты и запланируйте их замену.

Не вводите синоним ради разнообразия: в техническом тексте повтор точного термина полезнее стилистической вариативности.
