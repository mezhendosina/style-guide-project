# Шаблон метода API

Используйте шаблон для справочной страницы одного метода. Если раздел не применим, удалите его или явно объясните отсутствие поддержки.

## Заголовок шаблона

````markdown
# [Действие над сущностью]

`POST /v1/resources`

[Что делает метод, когда его использовать и какое право требуется.]

## Авторизация

Передайте токен с областью доступа `[scope]` в заголовке `Authorization`.

## Параметры пути

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `resource_id` | string | да | [Назначение и ограничения.] |

## Параметры запроса

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `limit` | integer | нет | [Диапазон и значение по умолчанию.] |

## Тело запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `name` | string | да | [Формат, диапазон, nullable.] |

## Пример запроса

```bash
curl --request POST \
  --url https://api.example.com/v1/resources \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"name":"Example"}'
```

## Ответ

При успешном запросе API вернёт `201 Created` и созданный объект.

```json
{
  "id": "res_123",
  "name": "Example"
}
```

## Ошибки

| HTTP | Код | Причина | Что делать |
| --- | --- | --- | --- |
| `400` | `invalid_request` | [Условие.] | [Действие.] |

## Ограничения

- Идемпотентность: [правило].
- Rate limit: [значение и окно].
- Тайм-аут: [значение].
````

## Проверка полноты

Описание считается полным, если разработчик может сформировать корректный запрос без изучения исходного кода, различить основные ошибки и безопасно повторить временно неуспешную операцию.
