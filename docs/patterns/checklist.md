# Самопроверка документа

Пройдите список перед Pull Request. Неприменимый пункт отметьте как `N/A` и кратко объясните причину в описании PR.

## Задача и структура

- [ ] Заголовок называет задачу или объект.
- [ ] Первый абзац сообщает результат и область применения.
- [ ] Страница решает одну основную задачу.
- [ ] Предварительные условия указаны до инструкции.
- [ ] У страницы один H1, уровни заголовков не пропущены.
- [ ] Текст ссылки понятен вне окружающего предложения.

## Язык

- [ ] Текст обращается к читателю на «вы».
- [ ] Действия сформулированы в действительном залоге.
- [ ] В одном шаге одно основное действие.
- [ ] Нет слов «просто», «очевидно», канцелярита и рекламных обещаний.
- [ ] Термины соответствуют [словарю](../rules/terminology.md).
- [ ] Даты, время и единицы указаны однозначно.

## Техническая точность

- [ ] Код и команды проверены.
- [ ] Запрос и ответ согласованы между собой.
- [ ] Заполнители заметны, секретов и персональных данных нет.
- [ ] Для параметров указаны ограничения и обязательность.
- [ ] Ошибки содержат причину и действие по восстановлению.
- [ ] Для повторных запросов описана идемпотентность.

## Доступность

- [ ] Смысл не передаётся только цветом или положением.
- [ ] У информативных изображений есть альтернативный текст.
- [ ] Команды и важные данные доступны как текст.
- [ ] Заголовки образуют понятный список.
- [ ] Интерактивные элементы доступны с клавиатуры.

## Автоматические проверки

```bash
python3 scripts/check_docs.py
npx --yes markdownlint-cli2@0.23.3
.venv/bin/mkdocs build --strict
```

- [ ] Проверка структуры и ссылок завершилась без ошибок.
- [ ] Markdown-линтер завершился без ошибок.
- [ ] MkDocs собрал сайт в строгом режиме.
