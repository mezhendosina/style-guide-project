## Зачем этот гайд

Пользователь API должен быстро понять, что отправить, что вернётся и как исправить ошибку. Разные термины, скрытые условия и неполные примеры заставляют его угадывать. Этот гайд превращает удачные редакторские решения в повторяемые правила.

Правила применимы к справочникам методов, практическим руководствам, примерам кода, сообщениям об ошибках и release notes.

## Как пользоваться

1. Определите тип документа и задачу читателя.
2. Возьмите подходящий [шаблон](patterns/how-to.md).
3. Примените общие правила языка и оформления.
4. Проверьте результат по [чек-листу](patterns/checklist.md).
5. Отправьте изменение на ревью.

!!! tip "Если правила не хватает"

    Не копируйте случайное решение в несколько документов. Предложите новое правило через процесс из `CONTRIBUTING.md`: объясните проблему, покажите пример и зафиксируйте критерий проверки.
