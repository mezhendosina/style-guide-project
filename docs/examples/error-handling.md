# Обработка ошибок API

Настройте клиент так, чтобы он различал постоянные и временные ошибки, безопасно повторял запросы и показывал пользователю полезное сообщение. Это второй документ для апробации стайл-гайда.

## Прочитайте объект ошибки

API возвращает единый JSON-объект:

```json
{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "Превышен лимит запросов",
    "request_id": "req_a12f",
    "details": []
  }
}
```

Используйте `error.code` для логики программы. Поле `message` предназначено для диагностики и может измениться без новой версии API. Сохраняйте `request_id` в журнале: он помогает службе поддержки найти запрос.

## Выберите действие по HTTP-статусу

| Статус | Повторять автоматически | Действие |
| --- | --- | --- |
| `400` | нет | Исправить поля из `details` |
| `401` | один раз после обновления токена | Получить новый токен |
| `404` | нет | Проверить идентификатор и доступ |
| `409` | зависит от кода | Не повторять `idempotency_conflict` без изменения ключа |
| `429` | да | Ждать время из `Retry-After` |
| `500–504` | да | Использовать увеличение задержки и jitter |

Не повторяйте автоматически запрос, если не уверены в его идемпотентности.

## Настройте задержку

Для временных ошибок выполните не более четырёх повторных попыток: через 1, 2, 4 и 8 секунд. Добавьте случайное отклонение до 25%, чтобы несколько клиентов не повторяли запрос одновременно.

Если ответ содержит заголовок `Retry-After`, используйте указанное значение вместо своей задержки.

## Покажите безопасное сообщение

Не выводите пользователю трассировку, внутренний адрес или исходное тело ответа. Свяжите понятное действие с кодом ошибки.

=== "Неудачно"

    Что-то пошло не так. Error 500.

=== "Удачно"

    Не удалось создать заказ. Повторите попытку через минуту. Если ошибка сохранится, сообщите поддержке код `req_a12f`.

## Проверьте реализацию

Имитируйте ответы `401`, `429` и `503`. Убедитесь, что клиент:

- обновляет токен не более одного раза;
- учитывает `Retry-After`;
- не создаёт дубликат изменяющей операции;
- прекращает повторы после установленного предела;
- записывает `request_id`, но не токен и не персональные данные.
