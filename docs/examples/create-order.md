# Создание заказа

Создайте заказ для существующего клиента и получите идентификатор, по которому можно проверить обработку. Это первый из двух документов для апробации стайл-гайда.

## Перед началом

Убедитесь, что у вас есть:

- API-ключ с правом `orders:write`;
- идентификатор клиента;
- уникальный ключ идемпотентности для операции.

## Отправьте запрос

Передайте сумму в минимальных денежных единицах. Например, `129900` означает 1 299 рублей.

```bash
curl --request POST \
  --url https://api.example.com/v1/orders \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: 5b760a27-4a92-4578-9449-cfbaba79cba1" \
  --data '{
    "customer_id": "cus_123",
    "amount": 129900,
    "currency": "RUB",
    "description": "Подписка на 12 месяцев"
  }'
```

API вернёт `201 Created` и созданный заказ:

```json
{
  "id": "ord_7f42",
  "customer_id": "cus_123",
  "amount": 129900,
  "currency": "RUB",
  "status": "pending",
  "created_at": "2026-10-16T12:30:00Z"
}
```

Сохраните `id`: он понадобится для проверки статуса.

## Проверьте результат

Запросите заказ по идентификатору:

```bash
curl --request GET \
  --url https://api.example.com/v1/orders/ord_7f42 \
  --header "Authorization: Bearer YOUR_API_KEY"
```

Операция выполнена, если API вернул `200 OK`, идентификатор `ord_7f42` и ожидаемую сумму.

## Возможные ошибки

| HTTP | Код | Причина | Что делать |
| --- | --- | --- | --- |
| `400` | `invalid_amount` | Сумма меньше 100 | Передайте сумму от 100 |
| `401` | `unauthorized` | Ключ отсутствует или отозван | Создайте ключ и повторите запрос |
| `404` | `customer_not_found` | Клиент не найден в текущем проекте | Проверьте `customer_id` и проект ключа |
| `409` | `idempotency_conflict` | Ключ уже использован с другим телом | Создайте новый ключ для новой операции |

При сетевой ошибке повторите запрос с тем же `Idempotency-Key`. API хранит результат ключа 24 часа и не создаст дубликат заказа.
